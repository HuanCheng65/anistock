# 安易 QQ 机器人：开发说明

这份文档写给在**独立仓库**里开发 QQ 机器人的人或 agent。不需要看安易的代码仓库：这份文档就是需求和接口约定的全部内容。不清楚的地方，问运营者。

## 1. 背景

**安易（AniEx）** 是一个以番剧为题材的模拟股票交易网站：每部作品是一支股票，资金是虚拟的（单位叫"星辉"），不能充值，也不能提现。网站即将开放注册。

安易**不收集手机号、邮箱和真实姓名**。证明"这个账号属于谁"的唯一凭据，是账号绑定的 QQ：

- **身份验证**：账号绑定一个 QQ，就算完成身份验证。只有完成身份验证的账号，才能领取财政补贴、认购新股、进入排行榜。一个 QQ 只能绑定一个账号，一个账号也只能绑定一个 QQ，以此限制小号。
- **找回密码**：找回密码的验证码只发给账号绑定的那个 QQ。

本说明的范围是这两件事背后的机器人指令。机器人是 **QQ 开放平台的官方机器人**，需要同时支持私聊（单聊）和群聊。

## 2. 要做的事

| 指令 | 场景 | 作用 |
|---|---|---|
| `/绑定 <绑定码>` | 私聊 | 把发送者的 QQ 绑定到网页上生成绑定码的那个账号 |
| `/解绑` | 私聊 | 解除发送者 QQ 的绑定 |
| `/找回密码` | 私聊 | 为发送者 QQ 绑定的账号申请一个重设密码的验证码 |
| `/帮助` | 私聊、群聊 | 列出指令 |

查询资产、行情推送等功能以后再加，见 §8。

## 3. 安全要求（硬性）

1. **`/绑定`、`/解绑`、`/找回密码` 只在私聊中处理。** 在群里收到这三条指令时，不调用服务器，只回复"这条指令只在私聊中使用"。
   原因：群里发出的绑定码，任何人都能抢先兑换，把自己的 QQ 绑到别人的账号上，再用 `/找回密码` 夺走这个账号。
2. **身份一律用私聊消息事件里发送者的 openid。** 下文的 `external_id` 指的就是它。不用群成员 openid，也不用 QQ 号。
3. 绑定码和验证码**不写入日志**，也不在群里出现。
4. 机器人令牌由运营者提供，放在配置或环境变量里，不提交到代码仓库。

## 4. 服务器接口约定

| 项目 | 约定 |
|---|---|
| 地址 | `https://<安易域名>/api/v1/...`（域名由运营者提供，测试环境同理） |
| 认证 | 每个请求带请求头 `Authorization: Bearer <机器人令牌>` |
| 请求体 | JSON，请求头 `Content-Type: application/json` |
| 成功 | 2xx。各接口的返回见 §5 |
| 失败 | 非 2xx，返回体是 `{"code": "...", "message": "...", "details": {...}}`。**按 `code` 判断情况**；`message` 是给玩家看的中文，§5 没有列出的 `code` 可以直接回复 `message` |
| 令牌无效 | 401，`code` 为 `unauthenticated`，`message` 为“机器人令牌无效”。这说明配置有误，记录日志并提醒运营者，不要原样回复玩家 |
| 限流 | 每个令牌每秒 30 次。同一个 QQ 的 `/绑定`、`/找回密码` 各自每小时最多 5 次，超过时返回 429，`code` 为 `rate_limited`，响应头 `Retry-After` 是需要等待的秒数 |
| 服务器故障 | 5xx，或者连接失败：回复“服务暂时无法使用，稍后再试” |
| 接口文档 | 完整的 OpenAPI 文档在 `GET https://<安易域名>/api/v1/openapi.json`，不需要认证 |

所有时间都是带时区的 ISO 8601 字符串，例如 `2026-11-06T21:40:00+08:00`。

## 5. 指令详细说明

回复文案已经按安易的文案规范写好，请原样使用，`{}` 里是要填入的值。

### 5.1 `/绑定 <绑定码>`（私聊）

玩家先在网页"设置 → 身份验证"里生成绑定码。绑定码是 8 位字母和数字，显示为 `K7Q3-9MZD` 这种形式，10 分钟内有效。然后玩家私聊机器人发送这条指令。

绑定码原样传给服务器即可，服务器会忽略大小写和连字符。

请求：
```
POST /api/v1/bot/bindings
{"code": "K7Q3-9MZD", "platform": "qq", "external_id": "<发送者 openid>"}
```

成功（201）：
```json
{"binding": {"id": 3, "platform": "qq", "external_id": "<openid>", "scopes": ["read:account"],
             "created_at": "2026-11-06T21:32:10+08:00", "last_used_at": null},
 "account": {"id": 4, "username": "alice"}}
```

| 情况 | 回复 |
|---|---|
| 201 | 已绑定 {account.username}，身份验证已完成。可以领取财政补贴、认购新股、进入排行榜，也可以通过机器人找回密码。 |
| 指令里没有绑定码 | 发送“/绑定 绑定码”。绑定码在网页“设置 → 身份验证”中生成。 |
| 422 `bind_code_invalid` | 绑定码不正确或已过期。在网页“设置 → 身份验证”中重新生成。 |
| 409 `already_bound`，且 `details.side` 为 `"qq"` | 这个 QQ 已经绑定了另一个账号。先发送“/解绑”，再绑定。 |
| 409 `already_bound`，且 `details.side` 为 `"account"` | 这个账号已经绑定了其他 QQ。在网页上解除绑定后再试。 |
| 429 `rate_limited` | 尝试次数过多，1 小时后再试。 |

### 5.2 `/解绑`（私聊）

请求（openid 放进路径，需要 URL 编码）：
```
DELETE /api/v1/bot/bindings/qq/<发送者 openid>
```

| 情况 | 回复 |
|---|---|
| 204（无返回体） | 已解除绑定，身份验证随之取消。 |
| 404 `binding_not_found` | 这个 QQ 没有绑定账号。 |

### 5.3 `/找回密码`（私聊）

请求：
```
POST /api/v1/bot/password-resets
{"platform": "qq", "external_id": "<发送者 openid>"}
```

成功（201）：
```json
{"code": "K7Q3-9MZD", "expires_at": "2026-11-06T21:40:00+08:00", "account": {"id": 4, "username": "alice"}}
```

| 情况 | 回复 |
|---|---|
| 201 | 账号 {account.username} 的验证码：{code}，10 分钟内有效。在登录页选择“忘记密码”，输入用户名、验证码和新密码。验证码只用于本人找回密码。 |
| 403 `not_bound` | 这个 QQ 没有绑定账号，无法通过机器人找回密码。发邮件到 aniex@huanchengfly.top 联系运营者。 |
| 429 `rate_limited` | 尝试次数过多，1 小时后再试。 |

服务器端的规则，机器人不用另外实现：新的验证码会让旧的失效；验证码只能用一次，输错 5 次后作废；玩家在网页上重设密码后，他在其他设备上的登录全部失效。

### 5.4 `/帮助`（私聊、群聊）

不调用服务器，回复：
```
安易机器人
/绑定 绑定码：绑定 QQ，完成身份验证
/解绑：解除绑定
/找回密码：获取重设密码的验证码
以上指令只在私聊中使用。
```

### 5.5 在群里收到 5.1–5.3 的指令

不调用服务器，回复：这条指令只在私聊中使用。

### 5.6 其他输入

不认识的指令和普通聊天，私聊时回复 `/帮助` 的内容，群里不回复。

## 6. 文案规则

如果要新增回复，按这些规则写：

- 简短、正式、平实。不用语气词（哦、啦、呢）、网络用语和表情符号，不用感叹号。
- 称呼玩家用“你”，不用“您”；不用“我们”自称。
- 不用“请勿”“禁止”“不要”这类说法，改为说明怎样做。说明失败时用“无法”，不用“失败”。
- 中文与英文、数字之间加一个半角空格（“QQ 号”“10 分钟”）；标点用全角，引号用“”。
- 资金单位叫“星辉”，不叫“币”。

## 7. 需要你确认并反馈给运营者的事

**同一个人在私聊和在群里，官方机器人给的 openid 是否相同？** 查开放平台文档，或者实际测试一次，把结论告诉运营者。

- 如果不同，这一期没有影响，因为身份相关的操作全部在私聊里，用的都是私聊 openid。
- 但 §8 的查询类功能如果要在群里使用，就需要别的办法把群里的人对应到账号，比如平台提供的跨场景 ID。

## 8. 以后的功能（接口已就绪，这一期不做）

机器人可以代表已绑定的玩家读取数据：请求时额外加请求头 `X-Act-As: qq:<openid>`。权限是只读，交易接口还没有开放。可用的接口包括：

- `GET /api/v1/me`：资产概况
- `GET /api/v1/me/portfolio`：持仓
- `GET /api/v1/me/orders`：委托
- `GET /api/v1/leaderboard`：排行榜
- 行情、股票、资讯类接口
- WebSocket 推送 `/api/v1/ws`

各接口的格式见 OpenAPI 文档。

## 9. 测试与验收

运营者会提供测试环境的地址和一个机器人令牌，测试环境里已开放注册。准备工作：在测试网站上注册一个账号，签署开户流程里的风险揭示书。然后逐条验证：

1. 网页"设置 → 身份验证"生成绑定码，私聊机器人发送 `/绑定 码`：收到绑定成功的回复，网页上身份验证显示"已通过 QQ 完成"。
2. 同一个绑定码再发一次：提示绑定码不正确或已过期。
3. 在群里发 `/绑定 码`：只回复"这条指令只在私聊中使用"，网页上的状态不变。
4. 私聊发送 `/找回密码`：收到验证码。在网页登录页的"忘记密码"里重设密码，能用新密码登录；之前已登录的浏览器被登出。
5. 私聊发送 `/解绑`：网页上身份验证变为未完成。再发 `/找回密码`：提示没有绑定账号。
6. 1 小时内连续发送 6 次 `/找回密码`：第 6 次提示尝试次数过多。
7. 检查机器人的日志：不应出现任何绑定码或验证码。

也可以先用 curl 直接调接口，确认令牌和地址没问题：

```
curl -s -X POST https://<安易域名>/api/v1/bot/password-resets \
  -H "Authorization: Bearer <令牌>" -H "Content-Type: application/json" \
  -d '{"platform": "qq", "external_id": "test-openid"}'
```

预期返回 403，`code` 为 `not_bound`（这个测试 openid 没有绑定账号）。
