# 估值与信息流

本文替代“平滑估值”“去掉播出日下跌”两条局部修补，从整体上重新定义隐藏估值，以及它如何随信息变化。NPC、事件、分红、新股定价都以它为准。

---

## 1. 原则

1. **隐藏估值 = 只用公开信息的理性分析师，对公司未来现金流的最佳估计。** 仓库和数据都是公开的，高手可以自己算出来：这是给高手的深度，前提是它本身必须正确。
2. **估值只在两种时候变化：出现新信息，或者现金离开公司（除息）。** 其余时间只随折现率缓慢变化。
3. **不存在按公开日历就能白赚的规律。** 播出日、分红日、开盘、收盘都不能带来可预测的超额收益。
4. **波动是结果，不是目标。** 不规定日波动是多少，而是检验波动是否出现在该出现的地方（§7）。

## 2. 现状的问题（仿真实测）

| 问题 | 原因 | 后果 |
|---|---|---|
| 估值日波动约 9.8% | 用最近 7 天营收直接外推全部未来，每天的数据噪声都当成了信息 | 价格被噪声带着走，噪声又会均值回归，高手可以反向交易 |
| 每集播出当天估值固定下跌约 6% | 按“剩余集数”折算，播出即减 1；而这一集的收入其实是之后几天才陆续进账 | 按播出日历提前卖出、事后买回就能白赚 |
| 热度快讯和估值是两套系统 | 快讯只在 NPC 的看法上额外加一个冲击 | 前后不一致，冲击大小靠拍脑袋 |
| 转移支付凭空给玩家发钱 | 税收只分给玩家；没有整体的资金检验 | 40 个玩家时每人每季约多拿初始资金的 30% |

## 3. 模型

### 3.1 热度的结构

一部番在某个市场（欧美、中国、日本）某一天的热度，拆成两部分：

> 热度 = 作品水平 × 集内曲线

- **作品水平**：这部番“有多火”，每集之间缓慢变化（v1 的 `in_season_retention` 0.98 就是它的平均走势），开播前不确定性最大。
- **集内曲线**：一集播出后热度怎么随天数消化，我们已经按市场校准过（`sim/calibration/maturity.json`：Bangumi 的单集吐槽第 1 天达到 4 周总量的 66%，Annict 的观看记录更平缓）。完结后的走势用实测的完结后曲线。长篇连载没有明显的集内曲线，按日观测。

营收的算法不变：营收 = 外部需求 × 加权热度份额。份额是相对的：别的番火了，你的份额就小了。

### 3.2 作品水平的估计：根据“超预期”修正

每出现一个新观测（某市场某天的热度），先算出“按目前的估计，今天应该是多少”，再看实际比预期高多少：

> 新估计 = 旧估计 + 修正系数 ×（实际 − 预期）

- **修正系数取决于目前有多不确定**：开播前只有“想看”人数，不确定性很大，所以第 1 集的超预期会让估计大幅变化；看过的集数越多，同样幅度的超预期修正得越少。现实里，新番首播前后分歧最大，中后段走势稳定，和这一点一致。
- **观测噪声越大，修正越少**：每天的数据噪声（星期效应、采集波动）只按它可能携带的真实信息量计入，而不是全部计入。
- 这就是统计上的卡尔曼滤波。它不是“平滑”：真正的超预期会被完整反映，只有噪声被过滤掉。
- **参数全部从数据估计**：用上一季（7–10 月）的完整数据，估计观测噪声、集间变化幅度、开播前估计的误差。估计方法和结果写进校准报告。

### 3.3 从水平到估值

1. 用估计的作品水平和集内曲线，推出**未来每一天的预期热度**，包括已播各集还没消化完的尾巴、未播各集、完结后的衰减。
2. 按当前其他番的预期热度，推出未来每天的**预期份额**和**预期营收**，再扣运营成本、税、留存，得到**预期分红**。
3. **估值 = 未来预期分红的折现之和 + 公司账上的现金（每股）**。折现率 = 基准利率 + 股权风险溢价（不变）。

一集播出时：未来的预期收入一部分变成了“今天的实际收入”，进入公司账上的现金，总估值不会跳变。

### 3.4 盘中更新：热度快讯

- 当天有新集播出的番，播出后每小时抓一次单集吐槽数（每部一个请求）。
- 按“小时级”的集内曲线（用 Bangumi 吐槽的发帖时间校准），把“播出后 h 小时的吐槽数”换算成对这一集热度的观测，带着更大的观测噪声进入同一套修正（§3.2）。
- 修正后的估值立即生效，同时发一条快讯：“《X》第 5 集讨论量高于预期 32%”。玩家和 NPC 同时看到。
- 第二天日结用完整数据再修正一次，盘中估计自然被“确认”或“回吐”。

### 3.5 现金和除息

- 营收每天进入公司账户（已经是这样），所以估值里“账上现金”每天增加，抵消“未来收入”的减少。
- 每周日发放分红：现金离开公司，估值按每股分红下调，相当于现实中的除息。行情上标注“除息”，价格的下跳有据可查。

### 3.6 新股定价

发行价用同一模型、开播前的估计（只有“想看”人数等先验），按当时的不确定性打一个现实的发行折价。这样开播后的第一次修正，就是新股最大的不确定性来源，和现实一致。

## 4. NPC 和事件

- 价值型 NPC 心中的估值 = 公共估值 × 个人偏差（不变）。不再有单独的“事件冲击”项：所有信息都通过公共估值进入。
- 消息型 NPC 对估值的大幅修正做出反应（速度快、持仓时间短）。
- 以后接入的新闻（续作、延期等）也是对模型的修正：续作 = 增加未来的集数；延期 = 收入往后推；炎上 = 对作品水平的负面观测。同一入口。

## 5. 整体资金检验

每次仿真输出一张资金流量表：外部注入（营收）、流出（运营成本、制作委员会分红、制作费）、税收、转移支付、NPC 资金进出、利息。检验：

| 指标 | 要求 |
|---|---|
| 账本总和 | 恒为 0 |
| 货币总量（玩家 + NPC + 公司现金） | 一季内没有持续单向的增减 |
| 综合指数 | 不因资金注入持续上涨；长期跟随整体营收 |
| 玩家每季获得的转移支付 | 占初始资金的比例在合理范围内（按人头分给所有居民，NPC 也算） |
| 玩家与 NPC 的财富占比 | 不因规则漏洞持续向一方转移 |

## 6. 对现有代码的影响

- `engine/valuation.py` 和 Rust 的 `valuation.rs` 同步改成新模型（仿真、开服、线上共用一份公式定义）。
- 每日输入文件增加每集的数据：播出时间、各市场的逐日观测。采集器需要保留 Bangumi 单集吐槽的发帖时间（用于小时级曲线和热度快讯）。
- 估值的状态（每部番的作品水平和不确定性）存入数据库新表，每天日结和每次快讯后更新，重启后不丢。

## 7. 验收

| 检验 | 要求 |
|---|---|
| 预测是否准确 | 回放上一季：对“下一集热度”的预测区间，实际值落在 80% 区间里的比例接近 80% |
| 修正是否不可预测 | 估值每日修正与前一天的修正、星期几、播出日都不相关 |
| 波动出现的位置 | 播出后、快讯时的波动明显大于平常；没有新信息的日子接近 0 |
| 首播最激烈 | 首播后一周的估值变化幅度 > 中段 > 末段 |
| 日历策略 | 播出前卖出播出后买回、除息前卖出除息后买回：都不能跑赢买入持有 |
| 防薅羊毛 | 原有五种策略重新全部通过（跑赢按市值买入持有不超过 5 个百分点） |
| 资金检验 | §5 全部通过 |

以上都在回放仿真里检验，通过后再上线。
