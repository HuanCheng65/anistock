# 估值与信息流

本文替代“平滑估值”“去掉播出日下跌”两条局部修补，从整体上重新定义隐藏估值，以及它如何随信息变化。NPC、事件、分红、新股定价都以它为准。

---

## 1. 原则

1. **隐藏估值 = 只用公开信息的理性分析师，对公司未来现金流的最佳估计。** 仓库和数据都是公开的，高手可以自己算出来：这是给高手的深度，前提是它本身必须正确。
2. **估值只在两种时候变化：出现新信息，或者现金离开公司（除息）。** 其余时间只随折现率缓慢变化。
3. **不存在按公开日历就能白赚的规律。** 播出日、分红日、开盘、收盘都不能带来可预测的超额收益。
4. **波动是结果，不是目标。** 不规定日波动是多少，而是检验波动是否出现在该出现的地方（§7）。

## 2. 现状的问题（仿真实测）

| 问题 | 原因 | 后果 |
|---|---|---|
| 估值日波动约 9.8% | 用最近 7 天营收直接外推全部未来，每天的数据噪声都当成了信息 | 价格被噪声带着走，噪声又会均值回归，高手可以反向交易 |
| 每集播出当天估值固定下跌约 6% | 按“剩余集数”折算，播出即减 1；而这一集的收入其实是之后几天才陆续进账 | 按播出日历提前卖出、事后买回就能白赚 |
| 热度快讯和估值是两套系统 | 快讯只在 NPC 的看法上额外加一个冲击 | 前后不一致，冲击大小靠拍脑袋 |
| 转移支付凭空给玩家发钱 | 税收只分给玩家；没有整体的资金检验 | 40 个玩家时每人每季约多拿初始资金的 30% |

## 3. 模型

### 3.1 热度的结构

一部番在某个市场（欧美、中国、日本）某一天的热度，拆成两部分：

> 热度 = 作品水平 × 集内曲线

- **作品水平**：这部番“有多火”，每集之间缓慢变化（v1 的 `in_season_retention` 0.98 就是它的平均走势），开播前不确定性最大。
- **集内曲线**：一集播出后热度怎么随天数消化，我们已经按市场校准过（`sim/calibration/maturity.json`：Bangumi 的单集吐槽第 1 天达到 4 周总量的 66%，Annict 的观看记录更平缓）。完结后的走势用实测的完结后曲线。长篇连载没有明显的集内曲线，按日观测。

营收的算法不变：营收 = 外部需求 × 加权热度份额。份额是相对的：别的番火了，你的份额就小了。

### 3.2 作品水平的估计：根据“超预期”修正

每出现一个新观测（某市场某天的热度），先算出“按目前的估计，今天应该是多少”，再看实际比预期高多少：

> 新估计 = 旧估计 + 修正系数 ×（实际 − 预期）

- **修正系数取决于目前有多不确定**：开播前只有“想看”人数，不确定性很大，所以第 1 集的超预期会让估计大幅变化；看过的集数越多，同样幅度的超预期修正得越少。现实里，新番首播前后分歧最大，中后段走势稳定，和这一点一致。
- **观测噪声越大，修正越少**：每天的数据噪声（星期效应、采集波动）只按它可能携带的真实信息量计入，而不是全部计入。
- 这就是统计上的卡尔曼滤波。它不是“平滑”：真正的超预期会被完整反映，只有噪声被过滤掉。
- **参数全部从数据估计**：用上一季（7–10 月）的完整数据，估计观测噪声、集间变化幅度、开播前估计的误差。估计方法和结果写进校准报告。

### 3.3 从水平到估值

1. 用估计的作品水平和集内曲线，推出**未来每一天的预期热度**，包括已播各集还没消化完的尾巴、未播各集、完结后的衰减。
2. 按当前其他番的预期热度，推出未来每天的**预期份额**和**预期营收**，再扣运营成本、税、留存，得到**预期分红**。
3. **估值 = 未来预期分红的折现之和 + 公司账上的现金（每股）**。折现率 = 基准利率 + 股权风险溢价（不变）。

一集播出时：未来的预期收入一部分变成了“今天的实际收入”，进入公司账上的现金，总估值不会跳变。

### 3.4 盘中更新：热度快讯

- 当天有新集播出的番，播出后每小时抓一次单集吐槽数（每部一个请求）。
- 按“小时级”的集内曲线（用 Bangumi 吐槽的发帖时间校准），把“播出后 h 小时的吐槽数”换算成对这一集热度的观测，带着更大的观测噪声进入同一套修正（§3.2）。
- 修正后的估值立即生效，同时发一条快讯：“《X》第 5 集讨论量高于预期 32%”。玩家和 NPC 同时看到。
- 第二天日结用完整数据再修正一次，盘中估计自然被“确认”或“回吐”。

### 3.5 现金和除息

- 营收每天进入公司账户（已经是这样），所以估值里“账上现金”每天增加，抵消“未来收入”的减少。
- 每周日发放分红：现金离开公司，估值按每股分红下调，相当于现实中的除息。行情上标注“除息”，价格的下跳有据可查。

### 3.6 新股定价

发行价用同一模型、开播前的估计（只有“想看”人数等先验），按当时的不确定性打一个现实的发行折价。这样开播后的第一次修正，就是新股最大的不确定性来源，和现实一致。

### 3.7 v0.3.2 修订：联合滤波和“当时可知”的先验

回放上一季发现两类根本问题（`replay_report.html` / `replay_report_v032.html`）：9 月上市的秋季新股从上市到 11/3 中位数上涨 109%；有几部番在没有任何新数据的日子估值一天跌一半。原因和修正：

| 问题 | 原因 | 修正 |
|---|---|---|
| 开播前的预估偷看了未来 | 中国、日本两个市场的开播前预估用的是**最新**的 Bangumi/Annict 观众数（想看+在看+看过），夏季番的“开播前”其实是播完以后的数字，参数也是拿它拟合的 | 先验只用当天已有的数据，并在开播前一天冻结：欧美用当天的 AniList 列表人数；中国、日本按欧美的预估乘以拟合出的比例（`prior_bias`，在实际观测上拟合，没有未来信息）。以后若有开播前的 Bangumi/Annict 快照，就用它（这一支还没有数据校准） |
| 预估在开播前还会系统性上涨 | AniList 列表人数在开播前三周平均再涨约 40% | 先验加上“从今天到冻结那天”的预期增长和它的方差（`preair_growth`，按剩余天数拟合） |
| 三个市场各自为政；“没有数据”被当成“零” | 三个独立的滤波；某市场开播四周仍无数据就删掉，数据迟到时再从零开始 | **一个三维的卡尔曼滤波**：三个市场的作品水平相关（先验协方差有共同相关 ρ，最大似然拟合；v0.6.1 改为两两相关，§3.9）。一个市场超预期，会按协方差带动另两个市场；某个市场暂时没有数据时，它的估计由其他市场推出，数据来了只修正剩余的“超预期”部分。只有两种情况算零：作品没有对应的数据源（没有 Bangumi/Annict 条目，按游戏的营收规则那个市场确实没有收入），或者数据源明确报告为零且开播已满四周 |
| 开播前的“热度衰减”提前计算 | 热度路径从“今天”开始衰减，开播前的作品等得越久越“便宜”，开播临近时估值每天上涨约 2% | 衰减从开播那天开始；开播前作品已有的欧美热度（列表新增、趋势）带来的收入也计入 |
| 市场总热度的假设 | 总热度按“今天的水平不变”或按季度边界的峰值兜底，季度切换当天所有份额一起跳 | 总热度 = 每部已上市（含认购中）作品自己的预期走势之和，加上**还没上市的作品**：上一季同一时点的季番总热度 × 这一季还没上市的比例（按上一季新番的上市时间拟合，`season_listing`）。每一项都是期望，只随新信息变化 |
| 完结后的数据被当成“热度下滑” | 完结后的观测直接进滤波，按季中的衰减速度预测 | 完结一周后，观测先除以完结后曲线，水平不再衰减；季中衰减只用季中数据拟合 |
| 完结后的热度低估了一半以上 | 完结后曲线沿用 v1 在 AniList 上测的 0.40、0.30…、每周 ×0.78，比实际（尤其是长尾）陡得多；估值低估了完结后的收入，持有者稳拿超额 | 按市场分别拟合完结后曲线和长尾（营收实际用到的序列：欧美是观测值，中国、日本是重建序列）。**第一阶段起由长尾模型取代**（docs/v2-series.md §4：几周的过渡、底和两段衰减的超出部分，用 2018–2025 年的历史数据拟合，估值算到无限期） |
| 中国、日本的先验和欧美成固定比例 | 实测：AniList 上越火的番，在中国、日本相对越小（对数斜率 −0.40、−0.66）；固定比例高估了大作，进而高估了这两个市场的总热度 | 先验 = 截距 + 弹性 × 欧美预估的对数，弹性按市场拟合（中国 0.62、日本 0.38） |
| 季中衰减速度单一 | 实测：开播头几周衰减快，第 8 周以后慢得多；单一速度高估前期、低估后期（两季连播的作品尤其） | 衰减速度按开播后第 0–3、4–7、8 周以后分段拟合 |
| 留存利润没有算进估值 | 估值只折现 90% 的分红，每周留存的 10% 现金进入每股净资产，于是估值每天被这部分现金“意外”抬高 | 估值折现全部税后利润（分红部分和留存部分都归股东，留存的在退市时返还） |
| 完结那一周的热度跳升 | AniList 在完结那周记录大量“看完”，欧美热度约为前几周的 1.5 倍（中国约 1.1 倍） | 按市场拟合完结周的倍数，计入预期走势；完结周和完结后的观测按它换算回水平 |
| 一次性放出整季的作品 | AniList 只记一次播出，模型还按每周一集排期 | 两周没有新集就按已完结处理（以最后一次播出为完结） |
| 日本数据“迟到” | 不是用户晚记录：Annict 的节目表只列近期各集，前几集没有播出时间，重建序列时被丢掉 | 重建序列时缺的播出时间用 Bangumi 的日期补齐（Annict 自己有的优先）；第 0 周开始就有数据的作品从 38% 升到 82% |
| 新股上市当天估值跳一下 | 认购期间估值停在发行价，上市后第一次估值才加回折价和募资 | 认购期间也按模型估值；分配结果出来时（上市前一天）把募资计入每股净资产 |

参数全部从数据拟合（`sim/fit_valuation.py`，报告 `sim/calibration/valuation_filter.md`），并做了跨季节检验：只用夏季拟合、在秋季新番上检验，以及反过来。状态存在新表 `valuation_joint`（迁移 V3）；上线时用 `ANISTOCK_VALUATION_REBUILD=1` 从输入历史重建。

**数据源接入公告（2026-11-06）。** 一部作品第一次接上某个市场的数据源（每日输入的 `sources` 从无变有）时，营收和估值都会从当天起按新数据重算，可能大幅变动（例：11 月 5 日 20 部番接上 Annict，《侦探已经死了。第二季》的估值从约 4.0 重估到 9.07）。日结同时发一条公司公告（`system` 类，归在“公告”），标题如“《侦探已经死了。第二季》接入日本市场数据”，正文“日本市场的热度数据从今天起计入营收和估值。”现实依据是财务数据重述时的信息披露。上次看到的标记存在游戏状态 `sources:<公司>` 里；第一次看到某支股票时只记录、不发公告，所以上线当天不会给每支股票都发一条。

### 3.8 v0.6.1：欧美周内数据按天观测

欧美（AniList）热度每天公开，但滤波只在一集的一周结束后观测这一周的平均（`week_observation`），周内的消息最多晚一周才进入估值。回放里这是一条可预测的修正：周内已有几天比估值自己的预期高 25% 以上时，接下来 7 天估值平均再上修 +9.8%（低 12.5% 以上时 −6.7%）；秋季新番开播周尤其明显：中国、日本的第一批数据通过三市场的相关把欧美水平一起拉低，一周后欧美整周观测到达再修回（206814：−63%，一周后 +83%）。

**做法。** 一集播出后的第 j 天（j = 1..7）有了前 j 天的 log(热度 / 集内曲线) 的平均 ȳ_j，整周平均是 ȳ_7。把周内各天看成整周平均加一个“周内形状”偏差：ȳ_j = X + m_j + e_j，X 是整周平均（它本身 = 水平 + 整周噪声 r，原来就有），e = (e_1..e_6) 的均值 m 和协方差 W 在完整周上拟合（e_j = ȳ_j − ȳ_7，样本均值和协方差就是高斯的最大似然）。

**嵌套观测的卡尔曼处理（不重复计入）。** 前 n 天的 n 个平均是嵌套的，不是 n 个独立观测。它们对水平 L 的联合分布是 ȳ − m ~ N(L·1, r·11′ + W_n)。由 Sherman–Morrison，(r·11′ + W_n)⁻¹1 ∝ W_n⁻¹1，所以广义最小二乘组合 X̂_n = g′(ȳ − m)，g = W_n⁻¹1 / 1′W_n⁻¹1，是这 n 个观测关于 L 的充分统计量，它的噪声方差是 r + v_n，v_n = 1 / 1′W_n⁻¹1。于是每天只需观测一个 X̂_n（存为对每天数值的权重 `a`，和为 1，加偏移 `c`、方差 `v`），并且观测在“不含本周任何一天”的状态（`base`）之上做：第二天日结先回到 `base`，再观测 X̂_{n+1}。这和把第 n+1 天相对前 n 天的条件增量逐个观测等价，所以同一天的信息不会算两次；整周到齐时，整周观测照旧替换最后一个部分观测。中国、日本的新数据、热度快讯都同时作用在 `base` 上。

**设定，都由数据决定：**
- **方差随天数变化。** 播出当天（j = 1）的偏差方差约 0.6（播出时刻决定当天有多少，远大于整周的 r = 0.017），所以从第 2 天起才观测；GLS 让播出当天的权重很小。按天数 n 的方差再乘一个系数（1.62、1.38、1.47、1.34、1.34，n = 2..6），用“偶数编号的作品拟合 W、在奇数编号上算整周观测的预测似然”（及反过来）按最大似然选出：只用一半作品的约 120 周估 6×6 的协方差，另一半的偏差更大，不加系数时留出覆盖率只有 71%–73%。
- **形状分四套。** 开播那一周单独一套（开播周前几天低于整周：第 2 天的偏差 −0.31，之后各周是 +0.08 到 +0.18；按一个总的形状读，开播周的前几天会被读成水平偏低，正是开播周的问题方向）；之后各周按这一集播出那天欧美水平估计的三分位分三套（按上一周整周平均分档的试算，留出对数似然分三档比不分档高 111 和 281，差别主要在协方差；均值上小作品播出当天相对高、第 1–2 天相对低，不分档时 GLS 组合在大、小作品上偏差 ±0.02–0.03，060007c 用一个总形状时大作品的水平因此被系统地移动）。三分位在播出那天定下，本周不变。
- **范围。** 只在对齐播出日、每天都有数据的集周观测；完结那一周、完结后、长篇连载不观测（不在拟合样本里，照旧整周观测）。用 v0.6.0 的离群混合更新（`outlier_p`/`outlier_r`），单集尖峰在周中也主要按噪声读。
- 观测按整周观测的日历换算到今天（整周平均 + 3 天漂移是周后第一天的水平，往回移）。

**检验**（`sim/fit_valuation.py --partial-only`，标准输入，偶数编号拟合、奇数编号检验）：整周观测的 80% 区间覆盖率，只用 `base` 时 89.9%，加上前 2..6 天时 85.5%、79.0%、79.0%、77.4%、84.3%；整周观测的平均对数预测密度从 0.03 升到 0.42（2 天）、0.77、1.10、1.65、2.31（6 天）。可预测性：周内超预期（部分观测 − `base` 的均值）对之后 7 天欧美水平修正（扣除漂移）的斜率，不观测周内时 0.63，观测后 0.035（标准误 0.010）；作为参照，`base` 本身在一个整周观测之后的 7 天修正对它的超预期的斜率是 0.044，也就是剩下的部分和滤波本身的水平相当。

**观测量的选择。** 也比较了“前 n 天热度之和 ÷ 前 n 天曲线之和”的对数（一个累计量，直接按天数给方差）：它和整周对数平均有系统差（开播后各周第 6 天时均值差 0.042，对数平均只有 0.003），第 3 天起剩余方差也更大，所以用对数平均的 GLS。

（以上是 §3.8 第一版的数字。§3.9 改了先验之后按同样的方法重新拟合：偏差的均值、协方差几乎不变，留出检验中整周观测的覆盖率 90.8% → 85.8%、79.3%、78.6%、77.1%、84.3%（n = 0, 2..6），对数预测密度 0.03 → 0.41 … 2.31，修正斜率 0.63 → 0.027（标准误 0.010）。）

### 3.9 v0.6.1：三个市场两两之间的先验相关

**问题。** §3.7 的联合滤波只用一个共同的相关 ρ（0.53）描述三个市场开播时的“超预期”怎样一起变化。按天观测欧美数据（§3.8）之后，回放里仍有一条可预测的修正：开播后中国、日本的第一批数据经 ρ 把欧美水平一起拉动，几天后欧美自己的数据把它拉回（206814：中国、日本的第一批数据低于预期，欧美水平的估计当天 −45%，加上当天的欧美数据仍是 −29%，之后两天欧美数据把它拉回原处之上；改用下面的先验后为 −30% 和 −16%）。检验方法：在每部番中国、日本第一批数据到达那天，记下这批数据让欧美水平变了多少（T），再看之后 k 天欧美水平的修正（扣除漂移）R_k。模型对时，R_k 对 T 的回归斜率应为 0；实测（115 部在数据内开播、有当时先验的作品）R_1 −0.18（标准误 0.08）、R_3 −0.27（0.11）、R_7 −0.33（0.12）：传导过去的部分约三分之一会回吐。

**原因。** 直接看开播时三个市场相对先验的超预期（中国、日本用第一批数据，欧美用第一个整周），三对相关差别很大：欧美–中国 0.28、欧美–日本 0.26，中国–日本 0.67。一个共同的 ρ 只能取折中：对中国–日本偏低，对欧美偏高，于是中国、日本的第一批数据对欧美的修正约为数据支持的两倍。方差本身没有问题（欧美第一周超预期的方差实测 0.41，模型 0.47；中国 0.98 对 0.93；日本 0.34 对 0.35）。现实中这也说得通：中国和日本的观众对同一部番的反应更接近，AniList 的欧美观众是另一个群体。

**做法。** 先验协方差改为三个两两相关 [欧美–中国, 欧美–日本, 中国–日本]（`prior_corr`），和各市场的偏置、方差、弹性一起按联合滤波的最大似然拟合，各市场的动态（漂移、q、r）不变（`sim/fit_valuation.py --prior-only`）。结果 0.32 / 0.40 / 0.81，欧美的 p0 0.43 → 0.38；第一批中国数据对欧美水平的增益从 0.36 降到 0.20。参数文件没有 `prior_corr` 时三对都用 `rho`，与旧版逐位相同。

**检验**（标准输入，`sim/calibration/valuation_filter.json` 的 `fit.joint_prior_v061`）：
- 似然：样本内对数似然 +17.8（多 2 个参数）；留出检验（偶数编号拟合、奇数检验，及反过来）+9.9、+8.0；跨季节，秋季拟合用于夏季 +13.6，夏季拟合用于秋季 −8.4（夏季样本单独拟合出的中国–日本相关 0.91，偏高）。
- 下一次观测的 80% 区间覆盖率基本不变：样本内欧美 87.0% → 88.2%，中国 84.1% → 84.0%，日本 98.2% → 97.5%；留出检验欧美两个方向 90.0% → 90.0%、82.6% → 84.1%。
- 回吐：样本内 R_1、R_3、R_7 的斜率 −0.11（0.15）、+0.03（0.20）、+0.06（0.22），都在 0 附近；用一半作品拟合、在另一半上检验，R_1 −0.15（0.11）、R_7 −0.28（0.17），旧模型同样做法是 −0.19（0.07）、−0.40（0.11），而且传导本身变小（T 的标准差 0.42 → 0.26），所以剩下的可预测部分约是原来的一半以下，统计上与 0 没有区别。两个半样本各自拟合的欧美–中国相关是 0.17 和 0.53，一半作品估计相关的误差本身就不小，这是留出检验仍略为负的主要原因。
- §3.8 的部分观测在新先验上重新拟合（见上）。

**没有做的。** 中国、日本每集的第一个数值是播出后第 0–1 天的不完整计数，之后 1–2 天还会修正（相对最后的数值平均低 3.5% / 5.2%，方差 0.06 / 0.04）。和开播时 0.9 / 0.3 的先验方差相比，它对第一批数据的增益影响不到 6%，不是回吐的原因，没有单独建模。没有按季节拟合相关（只有两季），也没有给集间变化加跨市场相关（第一个欧美整周之后，欧美与中国、日本的协方差已接近 0）。

## 4. NPC 和事件

- 价值型 NPC 心中的估值 = 公共估值 × 个人偏差（不变）。不再有单独的“事件冲击”项：所有信息都通过公共估值进入。
- 消息型 NPC 对估值的大幅修正做出反应（速度快、持仓时间短）。
- 以后接入的新闻（续作、延期等）也是对模型的修正：续作 = 增加未来的集数；延期 = 收入往后推；炎上 = 对作品水平的负面观测。同一入口。

## 5. 整体资金检验

每次仿真输出一张资金流量表：外部注入（营收）、流出（运营成本、制作委员会分红、制作费）、税收、转移支付、NPC 资金进出、利息。检验：

| 指标 | 要求 |
|---|---|
| 账本总和 | 恒为 0 |
| 货币总量（玩家 + NPC + 公司现金） | 一季内没有持续单向的增减 |
| 综合指数 | 不因资金注入持续上涨；长期跟随整体营收 |
| 玩家每季获得的转移支付 | 占初始资金的比例在合理范围内（按人头分给所有居民，NPC 也算） |
| 玩家与 NPC 的财富占比 | 不因规则漏洞持续向一方转移 |

## 6. 对现有代码的影响

- `engine/valuation.py` 和 Rust 的 `valuation.rs` 同步改成新模型（仿真、开服、线上共用一份公式定义）。
- 每日输入文件增加每集的数据：播出时间、各市场的逐日观测。采集器需要保留 Bangumi 单集吐槽的发帖时间（用于小时级曲线和热度快讯）。
- 估值的状态（每部番的作品水平和不确定性）存入数据库新表，每天日结和每次快讯后更新，重启后不丢。
