# 改变估值的版本怎么上线

凡是会改变股票估值的版本（模型、参数、营收规则、续作期权），都用同一个脚本上线：

```fish
cd ~/anistock
bash deploy/revalue.sh vX.Y.Z
```

不改估值的版本（界面、接口、修 bug）照旧用 `ANISTOCK_VERSION=vX.Y.Z bash deploy/update.sh`。

## 脚本做什么

1. **检查**：不在 05:40–07:30（06:00 采集、06:30 日结）之间；必需的数据文件都在。
2. **停服、备份**：`data/backups/game-before-vX.Y.Z-时间.db`。
3. **安装**：下载这一版的程序，代码切到这一版的标签（配置、校准参数、Python 代码都和程序同一版本，不会再出现“程序是旧的、配置是 main 上新的”）。不重启。
4. **数据**：采集一次（`--skip-collect` 跳过，当天已经手动采过时用）；重建中国、日本序列；重新生成 7 月 1 日以来的每日输入。然后打印最近 8 天已上市作品的热度合计，并检查最后一天是否完整。不完整就停下。
5. **在副本上重建估值**：打印换算系数，以及新估值相对旧估值、相对现价的分布，还有上调、下调最多的股票。**停下来等你确认**：对照这一版上线文档里写的预期数字，不对就回答 N，什么都没改，服务停着。
6. **重新定价、启动**：股价对齐新估值，带 `ANISTOCK_VALUATION_REBUILD=1` 启动一次（启动后自动去掉），确认日志里重建了估值。
7. **核对**：正式数据库的换算系数和副本相同；估值/现价中位在 0.97–1.03。

任何一步失败都会停下，服务保持停止，最后几行写着怎么回到上线前（用第 2 步的备份）。修好问题后可以直接重新运行脚本（加 `--skip-collect`）。

## 你要做的

- 选一个不在早上的时间运行，第 5 步对一下数字，回答 y。
- 结束后打开网页看一眼，再按脚本最后一行发公告。
- 第二天早上日结之后，按这一版上线文档的“次日检查”看一下。

## 注意

- 采集器同一天第二次运行（部署时手动跑、脚本里跑）只补新作品的数据，不覆盖当天定时采集存下的快照和 AniList 趋势：日结读的数据始终是 06:00 那一轮的。确实要刷新时用 `uv run collect.py --refresh`。
- 脚本开始前检查今天 06:00 的定时采集已经成功跑完、今天的日结已经完成，否则不运行。
- 采集器每天 06:00 由定时器运行，日结 06:30 由游戏服务自己生成当天的输入，这两件事脚本不碰。
- 代码会停在发布标签上（detached）。之后普通更新也要写明版本：`ANISTOCK_VERSION=vX.Y.Z bash deploy/update.sh`，不写会提示。
