# v2 第 2 步：多主体 NPC 市场

目标：只有一个玩家时，市场也像真的一样——有成交、有分歧、有波动、对消息有反应；长期又围绕基本面运行，不被玩家轻易薅羊毛。

本步发布为 v0.3.0。规则写进 `docs/game-design.md`（注明现实依据，简化处标 ⚠️），参数全部放在 `server/game.toml` 的 `[market]` 段。

---

## 1. 为什么现在的市场不动

v1 的 NPC 只有三种：每支股票一个做市商（只挂单，不主动成交）、制作委员会（价格高于估值 1.3 倍才卖）、全市场 6 个随机散户。估值每天 06:30 才变一次，盘中所有 NPC 看的是同一个数，彼此没有分歧——没有分歧就没有成交。

真实市场的成交来自**参与者看法不同、看法随信息变化**。所以本步的核心是：很多个看法不同的 NPC，看法在盘中会漂移、会被事件冲击。

## 2. NPC 类型

学术上这一类模型叫“异质主体模型”（Chiarella–Iori 2002 的限价单簿版本、Lux–Marchesi 1999），能复现真实市场的典型特征：收益分布肥尾、波动聚集、短期价格不可预测。

| 类型 | 行为 | 现实依据 |
|---|---|---|
| **价值型** | 各自有一个“心中的估值” = 隐藏估值 × 个人偏差（偏差长期存在、缓慢漂移）。价格低于心中估值就买，高于就卖，偏离越大下单越多 | 基本面投资者；分析师之间的分歧 |
| **趋势型** | 看最近一段时间（几分钟到几小时，各人不同）的涨跌，追涨杀跌；仓位有上限 | 技术派、动量交易 |
| **消息型** | 平时不动；事件发生时（开播、完结、热度快讯、以后的新闻）按事件方向和强度交易，几小时内逐渐收手 | 事件驱动交易 |
| **散户型** | 小额、随机，偏好热门股，晚上比白天活跃 | 散户噪声交易 |
| **做市商**（保留并改进） | 双边报价；库存越偏离目标报价越偏；**最近波动越大价差越宽**；不再持有全部流通股 | 做市商的库存与风险管理（Avellaneda–Stoikov） |
| **制作委员会**（保留） | 价格高于估值 1.3 倍时减持 | 大股东减持 |

每个 NPC（做市商、委员会除外）有：
- 一个**关注列表**：5–15 支股票，按热度加权抽取。热门股关注的人多，流动性就好——和现实一致。
- 有限的**资金和持仓**，用完就做不了；不能卖空（卖空留到之后的版本）。
- 一个**活跃度**：下次行动的时间按指数分布随机抽取（泊松到达），所以 NPC 的动作天然分散在时间上，不会挤在同一时刻（压测里 p99 偏高的主要原因就是集中触发）。

规模初定：约 600 个 NPC（价值型 40%、趋势型 20%、消息型 10%、散户型 30%），最终数量由仿真校准决定。

## 3. 活跃度

每支股票的 NPC 活跃程度 = 基础值 × 热度^α × 日内曲线 × 事件放大。

- **热度**：用每日输入里的预期热度，热门股成交多、冷门股成交少。
- **日内曲线**：08:45–09:00 集合竞价；白天较平；午休小高峰；20:00–23:00 晚高峰（社团成员主要在晚上活跃，也和多数番剧播出时间一致）。
- **事件放大**：事件发生后活跃度临时放大，几小时内衰减回来。

预算：正常时全市场每秒几笔到十几笔 NPC 委托，事件高峰十倍以内。压测里 2 核在每秒 3000 笔以上仍然正常，余量很大。

## 4. 心中估值如何在盘中变化

隐藏估值每天 06:30 由日结更新一次（不变）。每个价值型 NPC 心中的估值 = 隐藏估值 × exp(个人偏差 + 事件冲击)：

- **个人偏差**：每人每股一个，随时间缓慢随机漂移（均值回归，半衰期几天）。保证任何时刻都有人觉得贵、有人觉得便宜。
- **事件冲击**：事件让所有 NPC 的估值同向移动一段，幅度按事件强度和可信度决定。
  - “基本面类”事件（例：以后的“宣布续作”）冲击会一直保留，直到下一次日结的隐藏估值把它“吸收”或“否定”。
  - “情绪类”事件（例：热度快讯、炎上）冲击按半衰期衰减。
- **偏差和冲击不存数据库**：由（种子，NPC，股票，日期）确定性地生成，重启后完全一样，不需要新表。事件冲击从事件记录重算。

## 5. 事件

统一的事件结构，本步只接内部事件，新闻以后接到同一个入口：

```
Event { company_id, kind, direction(-1/0/1), magnitude(0-10), credibility(official/media/rumor),
        source, ts, sentiment_or_fundamental, half_life }
```

本步的内部事件（都来自已有数据）：
1. **播出时间**：每集播出前 1 小时到播出后 2 小时，该股活跃度上升（粉丝“播出前布局”）。
2. **热度快讯**：每小时抓一次**当天有新集播出**的番在 Bangumi 上的单集吐槽数（每部一个请求），和同一部番前几集同一时间点的吐槽数比较，明显高于平常就是“神回”利好、明显低于就是利空。生成一条游戏内快讯，所有玩家同时看到。
3. **开播、完结、退市预警**：日结里本来就有的消息，同时作为事件。

所有事件在游戏内公告的那一刻起才生效，玩家和 NPC 同时看到。

## 6. 防薅羊毛（验收标准，不是附加项）

仓库是公开的，估值公式和数据源也是公开的，高手完全可以自己算出隐藏估值——这本来就是“基本面分析”，是给高手的深度。所以必须保证 NPC 不是提款机：

| 被测策略 | 要求 |
|---|---|
| 反复吃做市商的价差（低买高卖） | 扣除手续费后不赚钱 |
| 低于估值买入长期持有 | 可以赚，但不应明显超过“买入全市场持有” |
| 拉抬股价引诱趋势型跟风再出货 | 平均不赚钱（VCM 冷静期 + 价值型反向交易 + 委员会减持共同限制） |
| 挂单撤单影响做市商报价 | 做市商不看玩家挂单，只看成交和自己的库存；没有效果 |
| 推到 VCM 冷静期再反向操作 | 不赚钱 |

标准：一个赛季（约 13 周）回放里，以上任何简单程序策略的收益不超过“买入全市场持有”加若干个百分点（具体阈值在仿真后定）。达不到就继续调，设计不算完成。

**NPC 的财富不能漂移**：NPC 是玩家所有交易的对手方。整体上 NPC 一个赛季的盈亏应接近 0。NPC 资金用完时，从“外部世界”账户获得缓慢、有上限的资金流入（每周不超过一定比例），资金过多时流出——相当于基金的申购赎回，账本依旧总和为 0。

## 7. 校准：在 Rust 里用真实引擎做仿真

不另写仿真器，直接用 Rust 引擎（内存模式、不写数据库、时钟加速）回放本季真实的每日输入文件，同一个种子结果完全可复现。几分钟跑完一个赛季。

指标与目标：

| 指标 | 目标 |
|---|---|
| 每支股票成交间隔 | 正常时几分钟一笔，热门股更快 |
| 日内波动（日收益标准差） | 2%–5%；大事件日明显放大 |
| 收益分布 | 肥尾（峰度 > 3） |
| 波动聚集 | 收益绝对值的自相关为正，缓慢衰减 |
| 短期可预测性 | 1 分钟、1 小时收益的自相关 ≈ 0 |
| 价格回归估值 | 价格/估值 的偏离半衰期为几天 |
| 买卖价差 | 热门股约 0.5%–1%，冷门股更宽 |
| NPC 整体盈亏 | 赛季内接近 0 |
| 第 6 节的被测策略 | 全部达标 |

仿真输出一份报告（图表 + 指标表），作为 v0.3.0 的验收材料。

**标准输入集。** 回放必须用和模型同一版本的每日输入。v0.3.2 起估值需要输入里的 `prior`（开播前一天冻结的“当时可知”预估）、`observed`、`sources`；用旧格式的输入回放，每部番的滤波都只能从第一批数据起步，估值会滞后于公开热度，“买最热的三支持有”之类的策略就会虚高（实测：旧输入下 hold_hottest +114% 对买入持有 +39%；标准输入下低于按市值买入持有）。所以 `marketsim` 遇到缺这些字段的输入会直接报错（`--allow-old-inputs` 才放行，只用于对比），服务器每次日结也会警告。

## 8. 上线时的持仓迁移

现在每支股票的流通股基本都在做市商手里。v0.3.0 启动时做一次性迁移（数据库迁移 002，先自动备份）：

- 做市商保留目标库存（例如流通股的 20%），其余按当前价格转给价值型和散户型 NPC，NPC 用从外部世界账户获得的资金付款；做市商多出的现金退回外部世界账户。
- 全部走账本，记录原因 `npc_rebalance`，总和为 0；玩家的持仓和资金不受任何影响。

## 11. 流动性（v0.3.4）

玩家反馈：价差大、挂单很久不成交。原因是做市商太薄：每档几百币，一笔一万币的单子就能吃穿整个盘口。

**做市商改成"指定做市商"（交易所的 DMM 制度）：**

- 报价围绕市场价，不再围绕隐藏估值（`mm_anchor_to_price = 1`）。做市商不知道估值，把价格拉回估值是价值型 NPC 的事。价值型 NPC 因此增加到 3 倍（`n_value`）。
- 版权方把 20% 的股份借给做市商（`mm_loan_frac`），相当于发行人把股票借给指定做市商，保证报价背后有库存。场外按最新价划转，钱由外部世界账户出，不成交、不动价格。
- 最小报价量：每档至少 1,500 币（`mm_quote_min`），共 5 档，档距为半个价差的一半。
- 库存管理只调整报价数量（`mm_size_skew`），不调整报价价格。以最新价为锚时调价格会自我强化：做市商压低报价，下一笔成交也就压低了最新价。
- 遇到信息事件时报价放宽、数量减小（`mm_event_widen`）：开播前 1 小时到热度快讯后 2 小时、事件发布后 2 小时、开盘后半小时。逆向成交（上次报价后的成交到这次已经亏钱）也会放宽报价（`mm_toxicity_mult`）。

**自适应流动性：玩家活跃时 NPC 让位，玩家不在时 NPC 补位（`adapt_*`）。** 代码已经写好，但默认关闭，v0.3.4 不启用：两个被测策略的结果在不同种子之间相差很大，暂时无法判断它是否过关。

按股票分别计量玩家的活跃度，取两部分之和：

- 玩家的成交额，30 分钟半衰期的指数平均；
- 玩家在中间价 ±2% 内挂了 5 分钟以上的单子。

只挂不成交、马上撤单的单子不算，所以刷单撤单造不出活跃度。

做市商"补位，不抢位"：

- 只补足目标深度减去玩家深度的部分，每边至少保留四分之一。
- 玩家的最优价离做市商自己的报价不远时，做市商不抢到它前面，而是排在它后面。离得远的坏价格不理会，所以挂坏价格拉不动做市商。

散户型和趋势型 NPC 的活跃度按股票缩放：玩家越活跃越少，最低 ×0.5，最高 ×2。价值型 NPC 不变，它们是锚。

**上线（已有数据库）：** 启动时先备份，再做以下三件事：

- 按配置补足 NPC 人数。新的价值型 NPC 只有现金、没有持仓，人数记在 `npc_population_extra`。
  - 现金只给配置的三分之一（`grow_cash_scale`）。在仿真里，一次补足全额现金会让整体价格水平在头两周高出约 3%；给三分之一时只高 1–1.5%。分两周逐步补足没有明显改善。
- 版权方借股给做市商，每支股票的完成情况记在 `mm_loan:<id>`。
- 做市商现金补到 `mm_cash`，已补到的水平记在 `npc_mm_cash`。

三件事都可以重复执行，重复不会再动。玩家的资金和持仓不受影响。

仿真工具：`marketsim --probe`（`--probe-players N`）加入 N 个普通玩家，测量以下几项：

- 价差
- 限价单成交等待时间
- 1k/10k/50k 币的冲击
- 5 人各 5 万币同时买入一支股票后价格偏离多久
- 做市商在每类对手方身上的输赢
- 做市商和玩家在同一价位的排队先后

另有两个被测策略：`spoof_scare` 挂大单把 NPC 吓退，`bad_price` 挂坏价格等 NPC 来成交。
