# 热度期货的前端

docs/design/futures.md §5 的展开。接口见 docs/api-v1.md §4.5a，文案按 docs/copywriting.md，界面风格沿用 2026-11-05 定的方向（浏览页偏财经杂志，交易区偏紧凑终端，移动优先，桌面多栏）。**本文是草案，等确认后再动代码。**

## 1. 原则

1. **以作品为中心。** 玩家关心的是“这部番”。股票、热度、期货是同一部作品的三个侧面，放在同一个作品页里，不另开一个期货入口。
2. **交易终端复用。** 报价、K 线、盘口、委托、成交明细这一套，股票和期货共用同一组组件，换的只是数据和下单表单。
3. **风险看得见。** 期货是玩家第一次接触杠杆和盯市。下单前看得到“每变动 1 点赚亏多少”和“占用多少保证金”；持仓时看得到“离追保还有多远”。
4. **预测不公开。** 和估值一样，模型对合约期平均指数的预测不在任何地方出现。玩家能看到的是已公布的指数、期内平均和市场价格。

## 2. 导航

底部导航不变，只改一处：

| 现在 | 改为 | 内容 |
|---|---|---|
| 股票 | 行情 | 顶部切换“股票 / 期货”；股票列表不变；期货列表见 §5 |

“新股”一栏暂时保留。等期货上线、看过玩家怎么用以后，再决定要不要把它并进“行情”的筛选里。

桌面端的侧栏同理。

## 3. 作品页（`/stocks/:id`）

页头（封面、标题、制作公司、播出进度）不变。页头下面加一排**品种切换**，只在有合约时出现：

```
股票   第 2 期   第 3 期
```

- 切到某一期，下面的报价、图表、盘口、委托、成交明细都换成这个合约的；桌面端右侧的交易栏同步换成期货下单表单。
- URL 记住选择：`/stocks/:id?f=合约 id`，可以直接分享一个合约。
- 下半部分的资料页签（经营 / 作品 / 公告 / 股东）加一个“热度”，放在最前。

### 3.1 期货的报价区

```
92.35  +1.2%                       第 2 期 · 11月7日–12月4日
前结算 91.25 · 持仓 1,280 手 · 今日成交 342 手
期内已公布 12/28 天，平均 88.60                     还剩 16 天
```

- 价格的单位是“点”，保留两位小数，不带货币符号。
- “期内已公布 12/28 天，平均 88.60”是最重要的一行：结算价就是这 28 天的平均。已经公布的天数越多，价格越应该靠近这个平均值。
- 合约在等最后几天的指数（expiring）时，这一行改成“交易已结束，等待 2 天的指数”；结算后显示“结算价 90.12”。

### 3.2 期货的图表

两条线画在同一张图上：

- **合约价格**：每日结算价（日线）或盘中成交（分时）；
- **每日指数**：合约期内已公布的每日指数，画成柱，柱上叠一条“期内平均”线。

玩家一眼就能看出价格是高估还是低估了剩下几天的热度。图例只写“价格”“每日指数”“期内平均”，不加说明文字。

### 3.3 热度页签

- 上面：过去 90 天的每日指数，按三个市场（欧美、中国、日本）分色堆叠；补值或替换过的日子画成虚线框，悬停显示原因（“数据缺失，按前 7 天平均补值”）。
- 下面：最近 28 天的明细表：日期、指数、三个分项、标记。
- 表格下方一行小字链接到规则页的“热度指数编制方法”（第 1 版），不放大段说明。
- 一部公司有多部作品时，按作品分组。

## 4. 下单

### 4.1 期货下单表单

```
开多   开空                    （有持仓时多一个：平仓）
价格  [ 92.35 ]  点     市价
数量  [ 3 ]  手
──────────────────────────
名义价值        2,770 星辉
占用保证金        416 星辉
手续费              1 星辉
价格每变动 1 点   ±30 星辉
```

- 按钮用“开多 / 开空 / 平仓”，不用“买入 / 卖出”。开多、开空、平仓都下同一个方向的单，只是文案不同：持有空头时“开多”会先平掉空头，表单上方用一行提示“将先平掉 2 手空头”。
- 最后一行“价格每变动 1 点 ±30 星辉”是理解杠杆最直接的数字，所以放在最显眼的位置。
- 可用保证金不够时，按钮置灰，下方写“可用保证金不足：需要 416 星辉”，再给一个链接去“我的”。保证金可以用持股作担保，靠融资补足。

### 4.2 第一次下期货单

1. 没有信用账户：表单换成一张卡片“期货交易需要先开通信用账户”和“去开通”按钮，走现有的开通流程（风险测评、知识测试、风险揭示书）。
2. 有信用账户、还没开通期货：做一次期货知识测试（5 题，题目覆盖：结算价是平均值、每日盯市、保证金和强平、价格每变动 1 点的盈亏），签《期货交易风险揭示书》。和融资融券的开通是同一套页面（`/assessment/futures-quiz`）。
3. 第一次提交时弹出确认框：标题“开多 3 手第 2 期？”，正文两行：“占用保证金 416 星辉”“热度指数每变动 10%，盈亏约 ±277 星辉”，按钮“开多”。之后不再弹。

## 5. 行情页的期货列表

每部作品一行，显示它当期的合约，下一期折叠在行内：

```
[封面] 作品名            92.35   +1.2%
       第 2 期 · 还剩 16 天   持仓 1,280
```

排序：持仓量（默认）、涨跌、剩余天数。筛选：我持有的。

## 6. “我的”

现在的“融资融券”卡片改名为**信用账户**，期货并进去，因为两者共用保证金和维持担保比例：

```
信用账户                           维持担保比例 182%
净资产 12.3 万 · 负债 2.1 万 · 可用保证金 3.4 万
期货保证金 4,160 · 未结算盈亏 −320          距追保：指数再跌 18%
```

- “距追保”是期货玩家最需要的数字：按当前持仓，指数（或股价）往不利方向变动多少会触发追保。没有持仓时不显示。
- 下面列期货持仓，每个合约一行：作品和期数、方向和手数（“多 3 手”“空 2 手”）、前结算价 → 最新价、未结算盈亏、占用保证金。点进去就是作品页对应的合约。
- 资产明细里，期货的每日盯市在流水里显示为“期货结算”，手续费为“期货手续费”。

## 7. 实时推送

后端还要补上期货的推送（`live.rs`）：合约报价、盘口、成交，以及“我的期货”的变化（成交、结算、追保）。订阅方式和股票相同，频道名加 `futures:` 前缀。这是后端的工作，放在前端开工之前。

## 8. 术语

docs/copywriting.md 的术语表补充：

| 术语 | 用法 |
|---|---|
| 热度指数 | 安易热度指数的简称；单位“点” |
| 合约、第 k 期 | 一个合约就是作品的某一期，界面上不出现合约代码（HF12），只在规则页和接口里用 |
| 开多、开空、平仓 | 期货下单的三个动作 |
| 结算价、前结算 | 每天日结时的价格；到期结算价单独叫“到期结算价” |
| 保证金、维持担保比例 | 沿用融资融券的叫法 |
| 未结算盈亏 | 自上次日结以来的盈亏，日结时划转 |
| 期内平均 | 合约期内已公布的每日指数的平均 |

## 9. 顺序

1. 后端：期货推送（§7）、期货开通流程（知识测试、风险揭示书、业务权限）。
2. 共用组件：报价区、图表叠加、盘口、成交明细支持期货的数据。
3. 作品页的品种切换和期货下单表单。
4. 热度页签。
5. 行情页的期货列表。
6. “我的”里的信用账户卡片。
7. 规则页（热度指数编制方法、期货合约规则）和新手指南（“用期货对冲”的例子）。
