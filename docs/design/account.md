# 开户与账户体系

v1.0 公开前的准备（`docs/roadmap.md`「公开前：开放注册、去掉邀请码」）。邀请码去掉以后，要解决四件事：

1. 脚本批量注册：用自己实现的工作量证明（PoW）挡住
2. 小号套利：取消小号能拿到的好处（转移支付、新股认购、排行榜）
3. 新手引导：改成开户流程，不再一进来就买入
4. 合规文本：用户协议、隐私政策、风险揭示书

做法参照真实券商：开户时签署协议和风险揭示书，做风险测评（适当性管理），每项业务单独开通权限。规则表的第三列写这条服务哪条原则（`docs/game-design.md` 开头的三条：1 尽量真实，2 易上手有深度，3 好玩）。简化处标 ⚠️，**待定**表示数值是建议的默认值，还没有定。

---

## 1. 已定事项

| 事项 | 决定 |
|---|---|
| 人机验证 | 自己实现的 PoW，不用 Turnstile 或其他第三方验证码（大陆用户加载第三方脚本不稳定；PoW 同时保护 scrypt 不被刷） |
| 邀请码 | 不删，改成注册模式开关：开放 / 邀请 / 关闭 |
| 账号数量 | 每人一个，写进用户协议 |
| 身份验证 | 绑定 QQ（QQ 开放平台的 openid，私聊官方机器人完成）。不收集真实姓名、身份证号 |
| 资金单位 | 「币」改为「星辉」 |
| 合规文本 | 用户协议、隐私政策、风险揭示书分为三份 |
| 脚本交易 | 允许，按公开的接口规范；爬网页、批量注册、绕过限流算违规 |
| 域名与部署 | 维持现在的子域名和服务器；暂不在页面上显示备案号 |
| 合规底线 | 不能充值、不能兑现、不能在账户之间转让；发现真钱交易就处理；活动不收费用 |

## 2. 账户等级

| 等级 | 条件 | 解锁 | 现实依据 | 原则 |
|---|---|---|---|---|
| **开户** | 注册（PoW）、同意用户协议和隐私政策、签署风险揭示书 | 买卖股票、查看全部行情 | 开立证券账户，签署开户协议和风险揭示书 | 1 |
| **身份验证** | 绑定 QQ | 转移支付、排行榜、新股认购（§4） | 实名认证；一个 openid 只能绑定一个账号，等于一人一户 | 1、3：小号拿不到好处 |
| **风险测评** | 填写问卷，得出 C1–C5（§5） | 是开通任何业务权限的前提；决定产品风险匹配的提示 | 投资者适当性管理 | 1、3 |
| **业务权限** | 风险测评加上各项业务自己的条件（§6） | 融资融券，以后的期货、期权 | 两融、期货、期权分别开户，各签一份风险揭示书 | 1、2：复杂功能逐级开放 |

开户以外的等级都不挡住玩游戏。没做身份验证、没做风险测评，照样可以买卖股票。

## 3. 注册

### 3.1 注册模式

`[account] registration = "open"`，可选 `open`（开放）、`invite`（需要邀请码，就是现在的行为）、`closed`（关闭）。改配置后重启服务生效。被批量注册时切回 `invite` 或 `closed`。

### 3.2 PoW

参照 ALTCHA 的做法：服务器随机选一个数，告诉浏览器这个数的哈希值，浏览器从 0 开始逐个尝试，找回这个数。最坏情况的耗时有上限，不像"哈希值开头要有 N 个 0"那样可能碰上很长的运气差。

| 项目 | 规则 |
|---|---|
| 出题 | `GET /api/v1/auth/challenge?purpose=register\|login` 返回 `{algorithm, salt, cost, max, target, expires, sig}`。服务器选 `n ∈ [0, max)`，`target = PBKDF2-SHA-256(password = n 的十进制, salt, iterations = cost)`，`sig = HMAC(secret, algorithm\|salt\|cost\|max\|target\|expires)`。服务器不保存题目 |
| 解题 | 浏览器在 Web Worker 里用 `crypto.subtle` 从 `n = 0` 开始逐个计算，算到等于 `target` 为止。用户填表时就在后台开始算 |
| 验证 | 注册、登录时提交 `{challenge, n}`。服务器依次检查签名、过期时间、`n < max`，再算一次 PBKDF2。都通过之后才计算 scrypt |
| 防重放 | 用过的 `salt` 记在内存里，过期后清除。挑战有效期 5 分钟，所以重启后内存清空的影响可以忽略 |
| 算法 | PBKDF2-SHA-256，浏览器原生支持，不需要 WASM。一次调用在浏览器内部连续算 `cost` 轮，用原生代码解题的提速有限 |
| 平时难度 | 注册：`cost = 5000`，`max = 1000`，中端手机平均约 1–2 秒（**待定**，上线前用真机测）。登录：`max = 0`，不需要 PoW |
| 自动加难 | 全站每分钟的注册和登录请求超过 `pow.surge_per_min`（**待定** 60）时进入高压状态：登录也要做 PoW（`max = 1000`），注册的 `max` 乘以 4。连续 10 分钟低于阈值后恢复 |
| 兼容 | 浏览器没有 `crypto.subtle` 时（一些内置浏览器），在表单处显示「当前浏览器无法完成验证，在系统浏览器中打开后重试」 |
| 机器人接口 | 用令牌认证，不经过注册和登录，不受影响 |

参数放在 `[api.pow]`：`cost`、`register_max`、`login_max`、`surge_per_min`、`surge_factor`、`expires_secs`。

### 3.3 限流和资源上限

先要确认用户是否在同一个校园网里（§12 问题 2）。如果是，全校共用一个出口 IP，按 IP 设的上限会在上线当天误伤所有人。所以按 IP 的上限放宽，主要靠 PoW 和"一个 openid 一个账号"来防小号。

| 项目 | 现在 | 改为 |
|---|---|---|
| 注册 | 和登录共用 `auth_per_min = 10` | 另外设 `register_per_ip_day = 20`（已实现） |
| 登录 | `auth_per_min = 10` | 不变 |
| 同一 IP 的 WebSocket 连接数 | `ws_per_ip = 8` | 32（已实现） |
| 全站 WebSocket 连接数 | 不限 | `ws_total = 2000`（已实现，按压测结果调整） |
| scrypt 同时计算数 | 不限（`spawn_blocking`） | `hash_concurrency = 2`，最多等 5 秒，等不到返回 503 `busy`（已实现） |
| IPv6 | 按完整地址计数 | 按 /64 合并计数（已实现） |

### 3.4 用户名

- 不能包含保留词：安易、AniEx、官方、管理员、运营、系统、客服
- 不能包含脏词表里的词（词表放在 `server/` 下，不进前端）
- 错误文案：「用户名不能包含“官方”等保留词」

## 4. 小号能拿到的好处

| 好处 | 新规则 | 现实依据 | 原则 |
|---|---|---|---|
| 每周转移支付 | 需要完成身份验证、注册满 `transfer_min_days`（**待定** 7）天，并且过去 28 天至少有 1 笔成交。不符合条件的那一份不发，平分给符合条件的人 | 福利要求居住或参保年限 | 1、3 |
| 新股认购 | 需要完成身份验证。认购金额不超过认购开始前 `ipo_mv_days`（**待定** 5）个交易日的日均持仓市值 × `ipo_quota_ratio`（**待定** 1.0） | A 股市值配售：前 20 个交易日日均市值 1 万元才有 1 个申购单位。⚠️ 天数按游戏时间压缩 | 1、3：小号要先投入资金才能多认购 |
| 排行榜 | 需要完成身份验证、成交满 `rank_min_trades`（1）笔（2026-11-07：一人一号之后，笔数门槛只需要挡掉从没交易过的账号）。注册天数 `rank_min_days` 定为 0（2026-11-06：身份验证已经一人一号，等待期只是让上线当天注册的人两周进不了榜）。不够条件的账号在「我的」里看得到自己的收益率，标为「未入榜」 | 基金评级要求有足够长的业绩期 | 3：不能用小号赌一把冲榜 |
| 融资融券 | 见 §6 | | |

**副作用：** 新账号前几天没有持仓市值，不能认购新股。这和 A 股新开户的人一样，要先持有股票。新手引导里会说明这一点。

### 4.1 对倒监控

用户协议规定在账户之间转移虚拟资产属于违规（风险揭示书第六条第 3 款）。所以对倒监控是合规措施，不只是防小号。

| 项目 | 规则 |
|---|---|
| 关联账户 | 过去 30 天里在同一 IP 登录过的两个账户 |
| 可疑成交 | 关联账户之间的成交，满足任一条件：成交价偏离成交时买一卖一中间价超过 `surveil_price_dev`（**待定** 5%）；或者占这支股票当日成交量超过 `surveil_volume_share`（**待定** 20%） |
| 记录 | 每天日结时写入 `surveillance_flags` 表 |
| 处理 | 只出报表，不自动处罚。管理员通过机器人令牌的管理接口查看，人工判断后按用户协议第五条处理 |

为此新增登录记录表 `account_logins(account_id, ip, at)`，保存 6 个月。这张表同时满足《网络安全法》对日志留存的要求。

已实现为命令 `anistock surveillance [天数]`（默认 7 天），只读数据库，在服务器上运行，不对外开放接口。价格偏离按当天该股的成交量加权均价计算（成交时的买卖盘中间价没有记录）。

## 5. 风险测评

### 5.1 问卷

8 题，每题 A–D 分别记 1–4 分，满分 32。题目和选项按 `docs/copywriting.md` 写。

1. 你参与股票交易或模拟交易的经验
   A 没有 B 不到 1 年 C 1–3 年 D 3 年以上
2. 你对安易交易规则的了解程度
   A 刚开始了解 B 了解买卖和分红 C 了解冷静期、新股认购等规则 D 了解融资融券
3. 你在安易的主要目标
   A 获得稳定的分红 B 兼顾分红和价格收益 C 主要获得价格收益 D 争取排行靠前
4. 你通常计划持有一支股票多长时间
   A 一季以上 B 一季左右 C 几周 D 几天以内
5. 持有的股票一周内下跌 20%，你通常会怎么做
   A 全部卖出 B 卖出一部分 C 继续持有 D 买入更多
6. 持有的作品口碑明显下滑时，你通常会怎么做
   A 尽快卖出 B 再观察几集 C 看股价是否已经反映 D 趁下跌买入
7. 你能接受的最大亏损
   A 10% 以内 B 10%–30% C 30%–50% D 50% 以上
8. 你对融资买入（借入资金买入股票）的态度
   A 不考虑 B 了解后可能少量使用 C 有把握时会使用 D 会经常使用

### 5.2 评级

| 分数 | 等级 | 描述 | 个性文案（已写入结果卡，**待用户确认**） |
|---|---|---|---|
| 8–12 | C1 保守型 | 优先保证本金，能接受较小的价格波动 | 完结之后再看 |
| 13–17 | C2 稳健型 | 以分红为主要收益，能接受短期的价格波动 | 看过口碑再追 |
| 18–22 | C3 平衡型 | 兼顾分红和价格收益，能接受一定的本金亏损 | 先看三集再决定 |
| 23–27 | C4 积极型 | 追求较高收益，能接受较大的本金亏损 | 首播当天就追 |
| 28–32 | C5 激进型 | 追求高收益，能接受本金大部分亏损，可以使用杠杆 | 看完预告就开始追 |

|---|---|

## 6. 产品风险等级和业务权限

产品风险等级高于投资者评级时，第一次买入前弹出警示，确认后可以买，不拦截。亏损可能超过本金的产品设硬门槛，不满足条件不能开通。

| 产品 | 风险等级 | 开通方式 | 现实依据 |
|---|---|---|---|
| 股票 | R3 | 开户即可 | 普通账户 |
| **融资融券**（已上线） | R4 | 完成身份验证；风险测评 C4 及以上；`margin.min_days` 为 0（2026-11-06：原来的 14 天只为防小号加杠杆，身份验证直接做到了这一点，上线当天也能开通）；净资产不低于初始资金的 50%（现有规则）；知识测试 10 题对 8 题；签署《融资融券风险揭示书》 | A 股两融：开户满 6 个月、20 日日均资产 50 万元、知识测试、签署风险揭示书。⚠️ 时长按游戏时间压缩 |
| 国债（第三阶段 3） | R1 | 不用开通 | 国债人人可以买 |
| 指数基金、主题基金（第三阶段 2） | R3 | 不用开通，评级不匹配时警示 | 基金销售的风险匹配 |
| 制作债（第三阶段 3） | 按信用评级 R2–R4 | 不用开通，评级不匹配时警示 | 债券投资者适当性 |
| 热度期货、预测合约（第三阶段 1） | R5 | 风险测评 C4 及以上；知识测试；有融资融券成交记录 | 期货开户：知识测试加交易经历 |
| 期权（待定） | 买方 R4，卖方 R5 | 分三级逐级开通：备兑和保护性策略 → 买入开仓 → 卖出开仓 | 股票期权的三级权限 |

融资融券的知识测试覆盖：保证金比例、折算率、维持担保比例、追加担保物、强制平仓、穿仓后收益率记为 −100%、利息和融券费用。题目以后单独写。

`docs/game-design.md` 两融那一行要改：原来"不设开户时长"的理由是邀请码已经限制了小号。去掉邀请码后，这条理由不成立了。

## 7. 开户流程和新手引导

### 7.1 现有问题

1. **反复出现**：是否完成引导记在浏览器本地（`prefs.ts` 的 `aniex.onboarded`），每次登录都检查（`LoginView.vue:37`）。换设备、换浏览器、在 QQ 内置浏览器打开，都会再出现一次。
2. **稀里糊涂买入**：第 3 步最显眼的是「买入 N 股」按钮，点一下就提交 1 万币的市价委托，没有确认，也没有说明。

### 7.2 新流程

| 步骤 | 内容 |
|---|---|
| 1 注册 | 用户名、密码；勾选「已阅读并同意《用户协议》和《隐私政策》」。PoW 在后台计算（已实现） |
| 2 安易是什么 | 一屏，合并现在的前两页：每部作品是一支股票；作品越受欢迎，公司营收越高 |
| 3 签署风险揭示书 | 全文；输入自己的用户名确认，相当于电子签名 |
| 4 开户回执 | 账号、开户时间；接下来可以做的事：绑定 QQ、风险测评。然后进入市场页 |

流程只在**注册后**出现一次（已实现）。登录时只有存在待签文件才进入，只显示「协议更新」和签署两步。中途选「稍后」的，各页面顶部显示「签署风险揭示书后才能交易」和「签署」链接。

### 7.3 第一次委托

- 第一次打开委托面板时，在面板里说明限价委托和市价委托的区别
- 新增「下单前确认」设置（已实现，存在浏览器本地，默认打开）：第一次按下单按钮时，在按钮上方显示「以 9.29 买入《作品名》100 股？」，按钮变为「买入」「取消」两个；改动任何输入都会收回确认。金额已经显示在上方的「预计花费」里，不再重复
- 风险揭示书里已经说明了市价委托的成交价可能偏离现价

## 8. 现有账号的迁移

| 项目 | 处理 |
|---|---|
| 开户 | 现有账号都视为已开户，不再显示开户流程 |
| 协议 | 下次登录时显示「协议更新」页，同意用户协议和隐私政策、签署风险揭示书。**签署前可以查看，不能委托**。真实券商在协议更新后，也要求客户重新签署才能继续交易；这一页只需要一分钟 |
| 身份验证 | 已经绑定 QQ 的账号直接算完成 |
| 融资融券 | 已经开通的保留，不要求补做测评和知识测试 |
| 排行榜 | 现有账号按 §4 的规则判断，满足注册天数和成交笔数但没绑定 QQ 的，提示绑定 |

## 9. 账号注销

用户协议和隐私政策都承诺可以注销。账本的收支必须平衡，所以交易记录只能匿名化，不能删除。

| 步骤 | 处理 |
|---|---|
| 条件 | 信用账户没有负债（融资欠款、欠券都已结清）；输入密码确认 |
| 委托 | 撤销全部委托，退回未分配的新股认购 |
| 持仓 | 按最新价转给 world 账户，和破产重整的做法一样（不是委托，不收佣金和印花税） |
| 现金 | 转给 world 账户 |
| 个人信息 | 用户名改为「已注销用户 #编号」；删除密码、QQ 绑定、登录记录、测评答案、协议签署记录 |
| 保留 | 账本和成交记录（匿名），保持市场数据完整 |
| 排行榜 | 移出 |

确认对话框：「注销账号？」，说明持仓和资金会被清空、不能恢复，按钮写「注销账号」「取消」。

## 13. 修改和找回密码

| 项目 | 规则 |
|---|---|
| 修改密码 | "设置 → 账号"，输入当前密码和新密码（`POST /api/v1/me/password`）。当前设备换发新的登录状态，其他设备需要重新登录 |
| 找回密码 | 账号绑定的 QQ 是唯一凭据。私聊机器人发送“/安易 找回密码”，机器人调用 `POST /api/v1/bot/password-resets` 取得 8 位验证码并回复；玩家在登录页“忘记密码”输入用户名、验证码和新密码（`POST /api/v1/auth/password-reset`），完成后直接登录 |
| 验证码 | 10 分钟有效，只能用一次，新码使旧码失效；输错 5 次作废；只保存 SHA-256；每个 QQ 每小时最多申请 5 次；重设接口另受按 IP 的登录限额约束 |
| 没有绑定 QQ 的账号 | 发邮件联系运营者。运营者核实后在服务器上运行 `anistock reset-code <用户名>` 生成验证码 |
| 旧的登录状态 | 登录 cookie 是无状态签名。记录每个账号最后一次改密码的时间（`account_security`），签发时间早于它的 cookie 不再有效；cookie 格式不变 |
| 为什么用验证码而不是链接 | 官方机器人发送链接通常需要在开放平台登记域名；验证码没有这个限制 |
| 安全前提 | 绑定和找回密码只在私聊中处理（`docs/qq-bot.md` §2）。群里发出的绑定码可能被别人抢先兑换，进而夺走账号 |
