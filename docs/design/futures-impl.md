# 热度期货的实现

docs/design/futures.md §6 第 6–7 步（期货引擎、做市商、检验机器人）在现有代码上的做法。规则以 futures.md 为准，这里只写代码怎么组织。

## 1. 已定（2026-11-07）

| 事项 | 决定 |
|---|---|
| 标的 | 作品自己的指数（不是公司指数），按作品的开播日分期 |
| 合约期 | 4 周；第 k 期是开播后第 4k−3 到 4k 周；第 0 周不开；同时挂当期和下一期 |
| 上市门槛 | 挂牌时模型对这一期平均指数的预测不低于 75；作品所属公司已上市 |
| 担保品 | 初始保证金可以用股票按信用账户的折算率充当；每日盯市的亏损付现金，不够的部分转为融资负债，按融资利率计息 |
| 做市商资金 | 每个合约从系统拨一笔固定资金，持仓有上限，到期收回，盈亏计入货币总量的监控 |
| 手续费 | 佣金率同股票，不收印花税 |
| 回放里的指数 | `sim/heat_history.py` 回填的真实数据（2026-01 起） |
| 营收切换之前的预测 | 平台规模、常数、中国和日本的衔接系数用 futures.md §3.7 的固定值，写在 `[futures]` 配置里 |

## 2. 代码怎么分

交易所分两层，代码也分两层：

- **撮合**（股票和期货共用一份）：订单簿、价格优先时间优先、连续撮合、集合竞价、冷静期、禁止自成交。
- **清算**（各写各的）：成交以后钱和货怎么动。股票是全额付款、按批次交收、收印花税；期货是不付货款、记净持仓、冻结保证金、每日盯市、到期现金结算。

不做全局改名（`company_id` → `instrument_id`）：只是名字变了，抽象程度没有提高，风险很大。

### 2.1 撮合：`src/matching/`

| 文件 | 内容 |
|---|---|
| `book.rs` | `Book`：买卖两边按价格、时间排序的委托号；插入、删除、下一个可成交的对手单、分档深度、集合竞价的均衡价格和参与的委托 |
| `vcm.rs` | 冷静期的纯规则：`Guard` 接口（前收盘价或前结算价、开盘参考价、冷静期的截止时间和价格区间、本日触发次数），`cooling`、`sanity_band`、`quote_band`、`vcm_anchor`、`vcm_band` |
| `mod.rs` | `Venue` 接口和两个撮合过程 `sweep`（连续撮合）、`uncross`（集合竞价） |

`Venue` 由每种品种实现，撮合过程只通过它和外面打交道：

```rust
pub(crate) trait Venue {
    fn book(&self) -> &Book;
    /// 挂单的账户和剩余数量；不再有效的委托返回 None
    fn resting(&self, id: i64) -> Option<Resting>;
    /// 这个价格现在能不能成交（冷静期；可能触发新的冷静期）
    fn allow(&mut self, price: i64) -> bool;
    /// 进来的委托在这个价格最多还能成交多少（股票看资金，期货看保证金）
    fn capacity(&self, price: i64, want: i64) -> i64;
    /// 清算一笔成交
    fn fill(&mut self, buy: i64, sell: i64, qty: i64, price: i64);
}
```

股票的 `StockVenue` 包住 `&mut Engine` 和一支股票，`fill` 调用现有的股票清算；期货的 `FuturesVenue` 同理。股票的 `Company` 和期货的 `Contract` 都实现 `Guard`，冷静期的规则只有一份。

### 2.2 期货：`src/futures/`

| 文件 | 内容 |
|---|---|
| `mod.rs` | `FuturesState`（合约、委托、持仓、每日结算价），载入和变更记录（`Change::Futures`） |
| `calendar.rs` | 按开播日分期、挂牌判断 |
| `orders.rs` | 下单、撤单：拆成平仓部分和开仓部分，开仓部分冻结初始保证金，检查持仓上限 |
| `clearing.rs` | `FuturesVenue`：成交时更新持仓和成本，平仓部分的盈亏经过清算账户，收佣金 |
| `settle.rs` | 日结：结算价（最后 30 分钟的成交量加权均价 → 做市商中间价 → 前结算价），盯市，到期结算 |
| `forecast.rs` | 合约期平均指数的预测（均值和标准差），供挂牌判断和做市商使用 |

和其他模块的衔接：

- **保证金**（`margin.rs`）：信用账户的数字里加上期货的浮动盈亏和初始保证金占用；维持保证金折算成负债并入维持担保比例；强平时先平期货。
- **日结**（`daily.rs`）：期货结算在信用账户的日终检查之前，检查看到的是结算后的资金。
- **做市商**（`market/futures_mm.rs`）：每个合约一个，报价围绕预测，价差随预测的标准差放宽。
- **检验机器人**（`sim/futures_bots.rs`）：futures.md §4.5 的五种，加上“股票加期货同向满仓”。

### 2.3 数据

迁移 `V19__futures.sql`（V18 是 API 交易的），表和股票分开：`heat_index`（游戏库里冻结的指数）、`futures_contracts`、`futures_orders`、`futures_trades`、`futures_positions`、`futures_days`（每日行情和结算）。清算账户是一个新的特殊账户（`clearing`，第一次盯市时创建），不计入货币总量，每天日结后余额为 0。

价格以 0.01 指数点为单位存整数；合约乘数存在合约上（1 点 = 10 星辉）。
