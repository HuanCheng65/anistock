# 程序化交易与 API 密钥

状态：已定（2026-11-07）。阶段一（只读）已上线（v0.6.8）；阶段二（交易）已实现，开关 `[api] trading` 默认关闭（§11）。⚠️ 表示相对现实的简化。

## 1. 为什么要做

用户协议第五条和 `docs/v2-account.md` §1 都写了"脚本交易允许，按公开的接口规范"，但接口里能下单的认证只有浏览器 cookie（`Caller::player()` 拒绝一切令牌）。写脚本的人只能先算登录 PoW、拿 cookie 再一直用，这既不在规范里，出问题也说不清算不算违规。本设计给脚本一个正规入口。

## 2. 已定事项（2026-11-07）

| 事项 | 结论 |
|---|---|
| 认证方式 | 每个账号自己生成的 **API 密钥**，不扩展 QQ 机器人令牌。`docs/api-v1.md` §3.2 的底线不变：机器人令牌泄露不能导致交易 |
| 开通交易权限 | 需要身份验证，并签署单独的《程序化交易风险揭示书》 |
| 排行榜标记 | 用 API 密钥下过单的账号在排行榜上显示“程序化”标记 |
| 分两阶段 | 先开只读（阶段一），检验机器人通过后再开交易（阶段二，§7） |
| 数值和其余细节 | 全部按草案的建议（2026-11-07 用户确认） |
| 只读密钥 | 开户即可，不要求身份验证：只读对市场没有影响，注册已经有 PoW 和限流 |

## 3. API 密钥

| 项 | 规则 | 现实依据 |
|---|---|---|
| 生成 | 只在网页上（cookie 会话）生成；明文只显示一次，形如 `anx_` + 40 位随机字符；数据库只存 SHA-256，比较用常数时间 | 交易所的 API Key |
| 数量 | 每个账号同时有效的最多 **5 个** | |
| 名称 | 生成时填一个备注名，1–20 字 | |
| 权限 | `read:account`（账户只读，和机器人绑定的权限同名）、`trade`（交易，阶段二）。生成时选，之后不能改，要改就重新生成 | 交易所 Key 的权限分级 |
| 有效期 | 可选 30 天、90 天、365 天，默认 **90 天**。过期即失效 | |
| 吊销 | 网页上随时吊销；吊销立即生效 | |
| 自动失效 | 找回密码（`/auth/password-reset`）时全部密钥吊销，注销账号时全部删除。主动修改密码时不失效 | 账号被盗后的恢复 |
| 使用记录 | 记录 `last_used_at` 和最后使用的 IP，在密钥列表里显示，方便发现泄露 | |
| IP 白名单 | 不做。⚠️ 现实中交易 Key 通常要求绑定 IP；家宽和校园网 IP 常变 | |

请求方式：`Authorization: Bearer anx_…`。和机器人令牌共用这个请求头，按前缀 `anx_` 区分。带了 `Authorization` 就忽略 cookie（现有规则）。

## 4. 能做什么

`Caller` 新增 `ApiKey { account, key_id, scopes }`，并在 `player()` 旁边加 `trader()`：

| 操作 | `read:account` | `trade` | 只能在网页上做 |
|---|---|---|---|
| 公开读接口（行情、资讯、新股、排行） | ✓ | ✓ | |
| `/me`、`/me/portfolio`、`/me/orders`、`/me/trades`、`/me/ledger`、`/me/asset-history`、`/me/credit`（读） | ✓ | ✓ | |
| `POST`/`DELETE /me/orders`（含信用委托，账户须已开通融资融券） | | ✓（阶段二） | |
| 新股认购、配股认购及撤销；`/me/credit/repay` | | ✓（阶段二） | |
| WebSocket 订阅 `me` 主题 | ✓ | ✓ | |
| 登录、注册、改密码、绑定码、签署文件、风险测评、知识测试、开通融资融券、破产重整、注销账号、管理 API 密钥 | | | ✓ |

- `trade` 权限在每次请求时检查：账号失去身份验证（解绑 QQ）后，交易密钥返回 403 `forbidden`，`details.required` 写明原因；重新验证后恢复，不用重新生成。
- 现有的交易门槛（未签署的新版文件、破产重整中等）对密钥同样生效。
- WebSocket：握手带 `Authorization: Bearer anx_…`，可订阅公开主题（含 `events`）和 `me`。密钥吊销或过期时连接以 4001 关闭。

## 5. 限流和资源上限

| 项 | 数值 | 说明 |
|---|---|---|
| 读写请求 | 每账号 **10 次/秒**（桶 20） | 沿用 `player_rps`。网页和所有密钥合计，不按密钥分别计 |
| 下单和撤单 | 每账号 **5 次/秒**（桶 10），另计 | 新键 `order_rps`、`order_burst`；同时也算在上一行里 |
| 每日委托 | 每账号 **5,000 笔/交易日** | 新键 `orders_per_day`；网页用户一天几十笔，不受影响 |
| 未成交委托 | 每账号同时最多 **100 笔**，每支股票 **20 笔** | 新键 `max_open_orders`、`max_open_orders_per_stock`；做市商不看玩家挂单，挂单本身影响不了报价，这条限的是引擎和推送的开销 |
| WebSocket | 用 API 密钥的连接每账号同时 **3 条** | 新键 `ws_per_account`；浏览器标签页不计入；仍受 `ws_per_ip`、`ws_total` 约束 |

- 超限返回 429 `rate_limited` 和 `Retry-After`；挂单超限返回 409 `too_many_open_orders`（新错误码）。
- 文档推荐脚本带 `Idempotency-Key`（已实现），网络重试不会重复下单。

## 6. 排行榜标记

| 项 | 规则 | 现实依据 |
|---|---|---|
| 判定 | 排行周期内（总榜：注册以来；周榜、季榜：本周期）有任何一笔委托来自 API 密钥，就标记 | 证监会 2024 年《证券市场程序化交易管理规定（试行）》要求程序化交易报告，交易所据此识别 |
| 显示 | 名字旁边一个“程序化”标签，不分开排名 | 交易所不把算法交易单独排名 |
| 数据 | 委托增加 `source`：`web` 或 `api`，同时给对倒监控用 | |

只读密钥不触发标记：标记的是谁在交易，不是谁在看盘。

## 7. 阶段二的前提：检验机器人

按 `docs/roadmap.md` 总则 3：3 个种子平均，相对买入持有的超额不超过 5 个百分点。种子顺序跑，不并行（服务器算力）。

| 被测策略 | 为什么现在要测 | 不通过时改哪里 |
|---|---|---|
| **抢快讯**：快讯、开播、完结事件公布后 1 秒内按方向买入，在消息型 NPC 几小时的跟进中卖出 | 事件对所有人同时公布，但消息型 NPC 分几小时下单（`docs/v2-npc-market.md` §2），程序比人快得多 | 改 NPC：一部分消息型在公布后几秒内就反应，到达时间随机化，不规定“不许太快” |
| **高频吃价差**：每秒报价、反复买卖做市商 | 单程手续费合计 7.5 个基点（佣金 2.5 + 印花税 5），做市商的价差在持续压力下要一直大于它 | 改做市商：成交加快时价差随之变宽（库存风险） |
| `v2-npc-market.md` §6 原有五项，反应延迟设为 0 | 原来按人的反应速度测过，程序可以做到零延迟 | 同上 |

### 7.1 检验记录（2026-11-07）

| 步骤 | 发现 | 处理 |
|---|---|---|
| 1. 第一次回放 | 快讯正文写着“估值随之修正：X → Y 星辉” | 删掉（commit 231bb5c，V16 改写已发的快讯）。估值不对外公开 |
| 2. 同上 | 模拟器每天只跑到 23:00，而快讯多在 01:00–04:00（播出后 3 小时），线上正在夜盘交易；模拟里它们被挪到第二天开盘 | 模拟器补上夜盘（到 04:00，`--no-night` 保留旧行为） |
| 3. 带夜盘 | `snipe_flash_2h` 相对买入持有 +7.1 个百分点：快讯后的下一次日结同向修正 87%–92% | 快讯的观测噪声口径错误，日结又重复计算同一集（`docs/v2-valuation.md` §3.4） |
| 4. 修好估值 | 日结同向修正降到 45%（利好）/ 65%（利空，两个方向的日结都平均下调约 1%）；但价格跟不上新估值，`snipe_flash` +9.1 个百分点 | 做市商随估值修正立即调整报价（`docs/v2-npc-market.md` §14） |
| 5. 做市商跟随，完整门禁（3 个种子，42 个机器人） | 相对买入持有：`snipe_flash` −22.7 / −13.5 / +3.1（平均 −11.0），`snipe_flash_2h` −22.1 / −1.0 / −1.4（平均 −8.2），`snipe_attention` 平均 −87.1；顺着快讯做 `ride_flash` −36.7，反着做 `fade_flash` −102.6。快讯后下次日结同向修正 45%（利好）、65%（利空） | 通过。唯一超过 +5 的选股机器人 `hold_hottest`（+13.2）是两支个股的表现（《学生会也有洞！》《无职转生 第三季》，见 `docs/roadmap.md` 总则 3），修复前同一种子 +22.4。副作用见 `docs/v2-npc-market.md` §14。估值的漂移参数另行重拟合（`prior-fix` 分支），合并后门禁全量重跑 |
| 6. 零延迟的其余策略（v0.6.9 代码，`inputs_fix5`，3 个种子；买入持有 −3.6% / −5.4% / −2.2%） | `snipe_premiere`（开播通知后开盘第一分钟买入，2 小时后卖）−13.0% / −19.7% / −12.9%。`snipe_finale`（完结通知后开盘第一分钟融券卖出，2 小时后买回）+2.1% / +2.8% / +2.7%，但 12 笔卖空的已实现盈亏合计约 0：收益来自资金闲置而买入持有为负，不是交易本身。`scalper_fast`（每秒在 5 支最热股票上比做市商高/低一档报价）−30.6% / −47.6% / −41.2%，比每分钟报价的 `scalper`（−23.4% / −23.0% / −18.6%）亏得更多：成交对手主要是价值型 NPC（逆向选择） | 通过。线上时序：快讯的新闻和做市商的重新报价在引擎的同一次处理里完成（`market/runtime.rs` `tick` → `apply_flash`），引擎单线程，API 下单只能排在其后。拉抬、挂撤单、冷静期反向三项没有单独做零延迟版本：做市商不看玩家挂单，趋势型 NPC 按分钟反应，快一秒没有作用 |

模拟里的快讯和线上一致：08:00–03:00 每小时一次，到播出后 26 小时；吐槽数是最终数 × 小时曲线 × 早期估计的误差（按拟合方差取对数正态）。只在第一次超过门槛时发快讯，其余只更新估值。

对敲：撮合层已经跳过自成交（`backend/src/engine.rs:1129`）；账号之间的对敲靠身份验证和 `anistock surveillance`，`source` 字段让报表能区分程序和人。

## 9. 风险揭示书要点（草案，正文以后按 `docs/copywriting.md` 写）

1. 程序发出的委托与手动委托效力相同，程序错误、网络重试、密钥泄露造成的损失由账户自己承担，不撤销成交。
2. 密钥等同于账户的交易权限，不要写进公开的代码仓库或发给他人。发现泄露立即吊销。
3. 本站可以调整频率限制和挂单上限；超出限制的委托会被拒绝。
4. 使用 API 下单的账号在排行榜上显示“程序化”标记。
5. 利用接口进行对敲、刷单，或绕过频率限制，按用户协议第五条处理。

## 10. 阶段一范围

- V15 迁移：`api_keys`。
- `GET`/`POST`/`DELETE /api/v1/me/api-keys`，只接受 cookie；只能授予 `read:account`，`trade` 返回 `invalid_request`。
- 认证：`Authorization: Bearer anx_…` 读 `/me/*`，限流和网页共用账号的桶；写接口返回 403 `forbidden`（`required_scope: "web"`）。
- WebSocket：密钥握手，可订阅 `me`；`ws_per_account`；吊销、过期、找回密码、注销时关闭连接。
- 找回密码吊销全部密钥，注销删除全部密钥。
- 设置页“API 密钥”一节：列表、生成（明文只显示一次）、吊销。
- `docs/api-v1.md` 增加 API 密钥一节；OpenAPI 增加 `api_key` 认证方式。

阶段二（交易权限、`trader()`、下单限额、挂单上限、`orders.source`、排行榜标记、风险揭示书）等 §7 的检验通过后再做。

## 11. 阶段二实现（2026-11-07）

- `Caller::trader()`：cookie 照旧；`ApiKey` 要有 `trade`，且 `[api] trading` 打开、身份验证有效、签署了当前版本的 `api_disclosure`，每次请求都查。用在下单、撤单、新股和配股的认购与撤销、还融资款；其余写接口仍是 `player()`（只能网页）。
- 生成 `trade` 密钥时同样检查；`scopes` 存为 `read:account,trade`。
- 限额（`[api.rate_limit]`）：`order_rps` 5 / `order_burst` 10（下单和撤单），`orders_per_day` 5000（内存计数，重启清零），`max_open_orders` 100、`max_open_orders_per_stock` 20。对网页同样生效。
- `GET /me` 增加 `api_trading { enabled, verified, disclosure_signed, disclosure_version }`；排行榜每行增加 `program`。
- 《程序化交易风险揭示书》是 `api_disclosure`（`web/src/legal/documents.ts`），版本在 `[account.documents]`，和 `margin_disclosure` 一样不进入“交易前必须签署”的列表。正文是按 §9 写的草稿，开放前需要确认。
- 用户协议第五条已经写着“不按本站公开的接口规范使用脚本……”，按规范使用即被允许，不需要改，也就不用让所有人重新同意。
- 开放：把 `server/game.toml` 的 `[api] trading` 改为 `true`，`deploy/update.sh` 后重启（配置随代码检出，不用打新版本）。也可以用环境变量 `ANISTOCK_API_TRADING=1` 临时打开。
